# impeccable audit of the Day view (2026-11-03)

Method: impeccable audit + critique (Operate mode), single context, as the brief asks for one report per auditor. Captures: the Playwright MCP browser was locked by a sibling auditor ("Browser is already in use"), so `impeccable-1440.png` and `impeccable-400.png` were taken with a standalone headless Chromium (Playwright 1243 build) against the live server on 5195, dark theme (the app's default, `index.html:2` sets `class="dark"`). Light theme was not captured because it is a stored toggle, not `prefers-color-scheme`. Live data cross-checked with `GET /api/ribbon` for the same window. No PRODUCT.md or DESIGN.md exists in the repo, so the incumbent code is the design authority.

## What the screen is for (2 lines, your reading)
The owner opens Compose and must know in five seconds what is moving, what is stuck, and what is waiting on him, lane by lane over the last day, plus whether the seats and money can carry the next few hours.
It is an Operate surface for one expert reader, so scan speed and truthful state outrank expression.

## Three things it does well
1. Honest unknowns: a count with no source reads "?" and never 0 (whatRules.js:8), lanes say "not recorded in this window" versus "nothing in this window" (DayRibbon.jsx:282), and the coverage line "start stamps on 85% of landings" tells the owner how far to trust the bars.
2. One source for marks and legend: the hatch patterns are defined once and reused by the legend swatches (DayRibbon.jsx:95-115), the now line plus tinted future gives an instant temporal anchor, and the keyboard path is real (focusable lanes, marks, pins, Enter/Space, Esc to cancel a drag, reduced-motion fallback for the flash).
3. Questions as navigation: the footer links "Is the process improving?" and "How far is 2.0 from flipping?" name the decision, not the page, and the phone layout drops the ribbon for a readable Now list instead of shrinking a chart to illegibility.

## One-paragraph direction
Turn the Day view from a timeline you study into a state you read. The top of the screen should answer "does anything need me" in one colored line, then the ribbon should give each of the three states that matter (working, waiting on review, waiting on you) its own unmistakable treatment, with "you" the only loud color on the page and stale or unknown work visibly dimmed instead of drawn as live. Fix the truth bugs first (one shared lane-state function for phone and desktop, regions drawn only over the rows they affect, AHEAD showing only what is ahead, ages on every working unit), because a beautiful ribbon that disagrees with itself loses the owner's trust faster than an ugly one. Then reclaim space: size the SVG to its container, shift the window to mostly past plus a compact "now" column, demote the date pickers and the repeated project chips, and floor the type at 11px. None of this needs a new visual language, the incumbent quiet dark palette and hatch vocabulary are sound, it needs sharper state encoding and a clear first read.
