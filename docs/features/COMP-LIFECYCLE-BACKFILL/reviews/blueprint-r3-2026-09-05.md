## Raw findings

1. **P1 — blueprint.md:1232: The new transition options are forwarded with the wrong names.** `_client.transition` receives camelCase arguments (`compose/server/lifecycle-guard.js:356`; `compose/server/stratum-client.js:349`), but the blueprint instructs forwarding `idempotency_key` and `expected_policy_checksum`. Those properties are discarded by the transport's destructuring, removing both replay identity and checksum protection. **Change:** forward `idempotencyKey` and `expectedPolicyChecksum`; translate to snake_case only inside `stratum-client.js`. Extend the wire assertions at `compose/test/stratum-client-guard.test.js:94`.

2. **P1 — blueprint.md:1272: Recovery can apply an unprotected first transition.** A crash after intent persistence but before transition execution leaves no ledger entry. If policy P becomes Q, recovery omits the expected checksum. Stratum finds no replay and applies under Q (`stratum/ts/src/guard/transition.ts:468`, `:571`, `:660`). The subsequent digest verification against persisted P then refuses permanently, after moving the guard. **Change:** retain the persisted checksum on recovery calls that may apply. On checksum mismatch, use read-only digest/history verification to recover an already-applied operation; never issue an unchecked transition. Test the pre-transition crash window.

3. **P1 — blueprint.md:217: The new write-plan schema rejects existing live history.** `write_plan.history` requires every entry to satisfy `BackfilledOccurrence`, including `recordedAt`, `origin`, `confidence`, and `evidence`. Actual live entries omit those fields (`compose/server/lifecycle-phase-history.js:32`), including lifecycle genesis (`compose/server/vision-routes.js:330`). The merge preserves these records, consistent with the design's no-migration requirement. **Change:** give stored history a schema supporting legacy/live entries alongside backfilled entries, and validate an intent containing a real genesis record.

4. **P1 — blueprint.md:1354: Recovery still does not consume the persisted write plan.** Recovery loads `plan`, but step 6.0 reads `probe.history` and `probe.written/skipped`; `probe` exists only on the fresh branch. It also uses `now` without restoring `op.started_at`, and never restores `op.notes`, although the retained completion writer consumes `notes` (`compose/lib/completion-gate.js:421`). Recovery therefore still has missing write inputs or substitutes retry values. **Change:** make both branches produce one complete write context and have every write consume it, including history, key lists, original timestamps, notes, and attestation.

5. **P1 — blueprint.md:997: The new divergence check refuses ordinary recovery after history persistence.** It re-merges the terminal occurrence, whose origin is `live` (§5.5), while dedup indexes only entries with origin `backfill` (§4.1:649). Once `updateLifecycle` persists the array (`compose/server/vision-store.js:239`, `:251`), the terminal remains incoming on retry and ties with its stored counterpart. Recovery refuses before reaching the later terminal-skip logic. **Change:** deduplicate the terminal by `operation_id`, verifying its immutable fields, before ties or divergence checks. Test recovery after successful step 6.0.

6. **P1 — blueprint.md:1333: The recovery suffix scan misses actual override entries.** Stratum emits overrides as `kind:'deviation'` (`stratum/ts/src/guard/transition.ts:765`), not `override`; migrations emit `graph_version` (`:838`), not `migrate`. After an authorized policy change permits movement away and back, overrides can leave `current_state` unchanged overall and bypass this scan. **Change:** reject later `transition` and `deviation` entries; handle state-preserving policy changes explicitly. Correct Flow A's setup too: an override requires a declared edge (`:757`), so the proposed terminal self-override needs an authorized graph change first.

7. **P1 — blueprint.md:1395: Passing the persisted flag does not make projection honor it.** The reused route callback hardcodes `consultGuard:true` (`compose/server/vision-routes.js:564`), and the verifier independently checks live `guardEnabled(cwd)` (`compose/server/completion-projection.js:136`). Thus false→true can spawn Stratum during an originally unguarded recovery, while true→false downgrades verification despite the persisted flag. **Change:** thread the effective flag through the callback and provide an explicit operation-level override of the verifier's live-config check. Assert both config flips through the real projection path.

8. **P2 — blueprint.md:1589: Dependency resolution still fails on the installed packages.** Both `req.resolve('@openai/codex-sdk/package.json')` and the fallback `req.resolve('@openai/codex-sdk')` fail with `ERR_PACKAGE_PATH_NOT_EXPORTED`: its exports expose only an import entry (`stratum/ts/node_modules/@openai/codex-sdk/package.json:24`). Also, resolving MCP's package manifest returns `dist/cjs/package.json`, not its package root, because of its wildcard export (`stratum/ts/node_modules/@modelcontextprotocol/sdk/package.json:62`). **Change:** support import-condition resolution from the real package context and verify the matching package name for every resolved root, including successful manifest resolutions, before creating symlinks.
