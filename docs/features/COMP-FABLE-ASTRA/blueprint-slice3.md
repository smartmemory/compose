## 5. D3 — checkpoint transaction, recovery, ship

**New `lib/wave-checkpoint.js`** owns Git planning/reconciliation; ConsumerFanoutArtifacts owns journal mutations. At first configured admission pin target repository, baseCommit=HEAD, baseTree and initialWorkingTree; reject a pre-existing unowned wave ref or unresolved Git merge. The initial dirty parent snapshot is preserved as evidence; worker wave 1 starts from the base commit, consistent with the design's base. A checkpoint captures the integrated parent tree including preserved initial dirty content; that does not by itself authorize staging unrelated paths at ship.
Change `#ensureWorktree` base selection at `lib/consumer-fanout.js:542`: configured wave admission's pinned baseCommit, otherwise existing HEAD. Every item in one wave, including later promotions/retries, uses that same base even if a ref subsequently moves. New admissions after checkpoint publication use its tip; merge retries without an approved checkpoint still use the previous tip. Worktree reconstruction retains the recorded base/witness (`:482-511`). No checkouts of the user's branch.
`prepareMerge` keeps its complete immutable ordered-diff/witness transaction (`lib/consumer-fanout.js:971-985`); additionally record epoch, checkpoint parent and `gateOrdinal` (number of earlier gate_resolved events for this gate at preparation). `applyMerge` keeps its temporary-index three-way integration into the parent working tree and witness verification (`:1007-1173`). Do not substitute git merge into the parent or commit each worker separately.
Extend the common build gate wrapper at `lib/build.js:4452` through its post-ack section `:4550-4574` (and GSD at `lib/gsd.js:699-704`) with this ordered protocol:

1. Prepare transaction and apply accepted diffs using current cancellation fences. Preserve pre-gate crash hook and nonapprove rollback. Send token-bound gate resolution; confirm actual approve, not merely requested approve. Store/verify gate ordinal and source snapshot before the call so acknowledgement loss is recoverable.
2. After approval is confirmed, derive checkpoint tree from transaction.witnessChain.at(-1), not an unguarded later snapshot. Verify parent working tree is that witness at the immediate checkpoint seam. Keep each wave's integrated witness, including an empty-patch wave.
3. `git commit-tree <tree> -p <parentCommit>` creates an object with flow/wave/gateToken in the message; pin identity/timestamps/message for reproducible recovery. Fsync a prepared checkpoint record with its exact commit/tree/parent/token/wave number **before** publishing the ref. Commit object creation may precede the record; an unreferenced object after a crash is harmless.
4. Validate ref with `git check-ref-format`; `git update-ref refs/heads/compose/wave/<flowId> <commit> <expectedOld>` publishes using CAS (zero OID for initial creation). Never update HEAD, check out the wave branch or use git commit in the parent. Journal `state:published`, replicate checkpoint evidence, then project stream.
5. Only after durable publication/evidence may cleanup drop that checkpoint's diff payloads/worktrees. Add scoped cleanup by transaction tokens; retain journal identities, findings, model bindings and checkpoint records. New admissions remain blocked until this sequence/recovery finishes. A checkpoint failure is a checkpoint error, not merge repair or a request to revise an already-approved gate.

Wave number counts approved checkpoints (1-based), not run.rounds or per-item generations. A merge revise before approval creates no checkpoint; repeat acknowledgement/recovery of one token creates exactly one. Subsequent repair waves append one checkpoint each. Cancellation before approval rolls back through the existing path (C18). A cancellation after an already-confirmed durable approval must preserve that prior checkpoint for inspection; never delete the wave branch in cancellation cleanup.

**Resume table.** First verify YAML/engine/profile pins (`verifyConsumerRunRevision`, `lib/consumer-fanout.js:1317`), then reconcile checkpoint obligations inside `recoverAdvancedConsumerArtifacts` (`:1390`), before its current cleanup at `:1430`. Invoke on ordinary resume (`lib/build.js:3019-3032`) and terminal/cancelled recovery (existing call `:2983`). Gate ordinal identifies the old decision even when a later same-named gate is waiting; do not rely on present gate status. Match event decision plus the journal's recorded token/ordinal/epoch, never infer approval from tree shape alone.

| Durable journal / engine decision | Actual wave ref | Action before dispatch or cleanup |
|---|---|---|
| No checkpoint obligation; first wave | Absent | Admit from pinned base; create no commit until approval. |
| Merge applied, gate token still waiting | Previous tip/absent | Existing witness-prefix recovery; resolve that gate first. No checkpoint for unapproved work. |
| Engine approved at recorded ordinal; no prepared checkpoint | Previous tip/absent | Use retained transaction/final witness to create prepared checkpoint, then publish; do not re-run tasks or gate. |
| Prepared or published checkpoint J; journal ahead of branch | J.parentCommit (or absent for first wave) | Re-apply retained ordered diffs in a temporary recovery index seeded with J.baselineTree; verify resulting J.tree and exact commit object; CAS ref to J.commit. Do not re-apply to an already-integrated live parent. Retain evidence until finished. |
| Prepared J, published watermark still old (“branch ahead”) | Exactly J.commit with matching parent/tree/token | Trust ref; mark J published and finish evidence/cleanup. Zero diff reapplication and zero new commits. |
| Published J | Exactly J.commit | Idempotent; restore parent content only if it is at a known prior witness and needs materialization. Preserve legitimate post-checkpoint edits. |
| Several prepared obligations / ref at a recorded earlier checkpoint | Known ancestor checkpoint | Reconcile strictly in journal order, checking every parent/tree/token; never reset an already newer verified tip backwards. |
| Ref differs from every recorded intended hash; missing base/object/diffs needed for replay; parent tree diverged ambiguously | Unknown/diverged | `WAVE_CHECKPOINT_DIVERGED` or `WAVE_CHECKPOINT_EVIDENCE_MISSING`; stop, retain branch/diffs and explain. Never trust “ahead” based on ancestry alone or blindly reset user edits. |
| Run failed/killed/cancelled with prior published checkpoint | Verified recorded tip | Leave branch. Reconcile already-approved obligations before any eligible cleanup; roll back only unresolved unapproved merge transactions. |

The design's journal-ahead replay applies only while retained diffs exist. If a published ref is externally removed after cleanup, do not invent patches; report evidence loss (the journal still supplies the expected commit for inspection). A known commit object can be explicitly recovered later, but automatic divergent-history repair is outside this seam.
When parent content is already the last checkpoint plus later verify/review/report changes, recovery must not overwrite those changes with the checkpoint tree. Record an explicit materialization witness at publication; normal resume trusts that publication and preserves the live descendant work. If restoration is required and the live tree is neither a recorded witness nor safely mergeable, stop instead of invoking the existing broad restore on a historical transaction.

**Ship squash:** add `prepareWaveShip` at executeShipStep entry (`lib/build.js:5554`), before its test execution (`:5580-5586`); also wire the flow/wave context into GSD's executeShipStep call (`lib/gsd.js:554`). Use a temporary index: read-tree base, apply `git diff --binary <base> <waveTip> --` with `git apply --cached --binary -`, write-tree and require equality to the checkpoint tree. This computes the **squashed net tree** without staging the real index. In normal execution it is already materialized in the parent, so do not apply the same patch twice. The user's branch remains at base, so the existing selective stage/commit produces one commit with base as parent, no wave commits in its ancestry. Leave ship filtering/MCP enforcement/commit logic unchanged (C17); do not replace current content with tip at ship and lose report/verification edits. Publish no code remotely.
