## Decisions and actual API corrections

1. **Use committed Dispatch 1 APIs.** Journals initialize through `ConsumerFanoutArtifacts({routingBinding,routingAncestry})`; ancestry comes from `exportRoutingJournal()`. Admissions, issuances, token indices and per-issuance event tips are written through their public atomic APIs. `createContinuationIntent` receives `verifiedCompletedTaskIds`, not just caller-declared completion ids.
2. **Ordinary resume precedes profile refresh.** The old preliminary default-role preflight was deferred to the unconditional runner preflight after recorded routing/roles are loaded. Participating resumes restore the start's input roles and ignore current role/mode flags. Historical off runs stay off; a narrowly checked optional-routing-declaration-only spec change can reuse the historical authored-spec journal pin, without permitting other spec drift.
3. **Keep representation outside dispatch.** Build's wrapper retains its enumerable `{ok,resolved}` projection and exposes policy/provenance non-enumerably. Wave participation examines the static profile projection. Routing-only objects therefore do not enable legacy wave policy in off mode. The bundled projected digest remains exactly `310f9698e97212f695ce2ca752d724f90c1f233ab5855dcb33a26bd3ad786205`.
4. **Complete admission before launch.** Every recorded item is checked before committing the routing admission batch. Logical ids are planner ids where present, otherwise root/source/index-bound opaque identities. Generic observations gain no ownership, task-id, Git HEAD, worktree or checkpoint prerequisite. The stage-aware map is keyed by admission/scoped step/stage/logical item and checked against immutable baseline/root evidence before consumption.
5. **Source and consumer epochs are independent.** Source run/step/epoch/accepted token/full output digest are retained. The same source epoch cannot silently change token or output. A GSD merge revision retains the logical wave and advances its logical epoch; a continuation binds a transformed physical graph to the old logical allocations.
6. **Immutable epoch records.** Ordinary epochs bind their first issuance; later same-epoch tokens extend the retained issuance chain. Consumer epochs seal after the full wave has settled, or at the validated continuation/transition boundary. This avoids rewriting a growing issuance-id list in an immutable record. Reused continuation admissions retain their original physical provenance; new dispatch/epoch bindings carry the new source/run/index evidence.
7. **First-journal loss must be distinguishable.** A small fsynced initialization/location witness lives under the already protected per-start routing directory. A known initialized journal cannot be recreated after loss. An interrupted first initialization can finish only with the persisted binding and a snapshot proving no prior Compose execution. The journal remains external to the target, including in GSD via `consumerArtifactsRoot`.
8. **Pending plans are recovered by identity.** Feature-index discovery includes unbound requested intents and bound plans that never reached an issuance. A requested plan with one verifiable matching engine run is rebound/recovered; uncertain zero/multiple/unreadable matches refuse. Recovery never repeats the plan RPC. Resume planning checkpoints retain predecessor identity until the new plan binds, so a crash cannot erase the old run link.
9. **Detailed GSD resume is additive.** The ordinary off return/error path remains `{tasks}`. The runner uses an internal identity-only read under the locks, then detailed validated bookkeeping for participation. Cumulative completion ids are checked against validated blackboard/result contents; conflicting records refuse. Prior source graphs and dependency removals are retained separately from the existing state files. Recorded gate/pre-merge inputs are reused on continuation.
10. **Q1 is a refusal.** Participating GSD ordinary profiles must match the existing bare dispatch. No GSD sidecar-application behavior was added.
11. **Execution settlement is conservative.** S1a uses matching token-bound accepted-dispatch evidence, not inferred acceptance from a later epoch or a dead driver. A failed call whose engine state lacks that evidence remains uncertain and blocks retry/continuation. Consumer prepared-artifact envelopes can complete the routing event chain and replay stepDone without relaunching a model. This preserves Dispatch 1's safety contract; it does not claim S1b failure/outcome attribution.
12. **No receipt expansion.** Routing-only fanouts do not emit the legacy proposed/observed item-model receipts. Routing source payloads remain local and are removed from the legacy receipt projection. No routing receipt spool, paid-call join, usageReport change, ledger materialization, learned selection, trial, exploration, feedback or repair-floor claim was introduced.
