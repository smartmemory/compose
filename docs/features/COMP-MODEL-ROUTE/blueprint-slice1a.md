## 2. New contracts and internal shape boundaries

Create JSON Schema files `(new)` at `contracts/routing-start.schema.json:1` and `contracts/routing-record.schema.json:1`, following metadata convention in `contracts/checkpoint.schema.json:1–12`: `_source:"docs/features/COMP-MODEL-ROUTE/design.md"`, `_roadmap:"COMP-MODEL-ROUTE"`, explicit `$schema`, `$id`, required fields and closed object shapes. Validate at every persistence read/write; S1b extends by an explicit version, not untyped outcome fields.

**RoutingStart v1 (new).** Immutable canonical JSON payload plus `rootDigest`; fields:
- `schemaVersion`, `policyVersion`, `fingerprintVersion`, `startId`, `seed`, `mode:"shadow"`, `createdAt` (minted once).
- `policy:{tolerance:0.05,candidateLadders,route_trials:[],route_explore:0}`; retain provider-specific candidate contents; coordinator is separate, never an ordered rung. These are pinned reservations, not S3 algorithms.
- `table:{version:"s1a-empty-v1",contents:[],contentDigest,ledgerCutoff:null}`; empty is valid and is S1a's production table. No live ledger read.
- `presetId`, original/effective spec identities, original static input and its digest, original sidecar, explicit runtime override map, merged static profiles, profile digest; exact pinned provider/model/effort/capability resolutions and output-contract closures/fingerprints.
- `staticResolutions` and `ordinaryInitialCandidates`, keyed by scoped step/stage, with original prior, winner/source/via and manual fallback provenance. Initial candidate equals baseline; it is not an admission.
- `calibration_feedback:false`, `calibration:""`, `cohort:"static"`. No prompt interpolation or derived feedback.
Canonical JSON recursively sorts object keys, preserves array order, rejects undefined/non-finite values, and encodes UTF-8. Root is SHA-256 of all payload fields except rootDigest. Input digest excludes only the declared routing transport keys, avoiding a root/input hash cycle. Retain exact table contents and verify its separate digest.

**RoutingRecord v1 S1a subset (new).** Tagged union: `plan-intent`, `run-binding`, `continuation-intent`, `epoch-binding`, `admission`, `issuance`, `issuance-event`. Every record carries schemaVersion/startId/rootDigest/id; immutable duplicate id requires identical canonical payload. No acceptance/cost/paid-call fields.
- Run binding: engine run/revision, effective spec digest, full recorded input digest, planIntentId, previousRunId/continuationIntentId (explicit null for fresh).
- Continuation: old run/revision, immediate source and filtered graph contents/digests, cumulative completed ids, ids removed on this transition, earlier completion chain refs, removed dependencies, old/new index maps, logical task/wave ids, prior engine/logical epochs, prior admission/issuance refs. Binding to the new run is a separate record.
- Admission: scoped step/stage, logical wave/epoch/task identity, allocation id, physical run/epoch, recorded input digest/provenance, candidate, static baseline, proposal, admitted route or refusal, `would`, and `repairContext:{state:"not-evaluated-s1a"}`. Ordinary task/item/generation are null. No floor claim.
- Issuance: record id/statistical key, admission reference, run/revision, scoped step/stage, engine epoch, itemIndex/generation or null, logical ids/epoch, engine issuanceToken, priorRecordId or null, immutable selected route/provenance. `would` equals static baseline in S1a.
- Issuance events: append-only `launch-intent`, `result-prepared` (exact stepDone envelope), `settled` (token-bound engine evidence), or `uncertain`; state is a derived projection, never a rewritten issuance or acceptance label.

**Recovery state machine (both runners):**

| Durable evidence | Required action before any model call/new plan |
|---|---|
| Start/intent prepared, plan not requested | Resume the same intent; persist requested event before its single plan call. |
| Plan requested, response/binding missing | Scan recorded inputs via findRoutingPlanRuns. Exactly one matching run → validate/bind/recover that pending plan; multiple, unreadable, or zero with uncertain RPC → ROUTING_PLAN_UNCERTAIN, no new plan. Recovering this already-created continuation is not resuming the old completed GSD run. |
| Run bound, first journal creation interrupted | Recreate only if intent/binding proves initialization phase and snapshot proves no Compose execution; otherwise missing journal is evidence loss. |
| Admission/issuance exists, no launch-intent | Verify exact token/state and immutable local records, append launch-intent durably, then launch once. |
| launch-intent exists, result/settlement unknown | Matching engine accepted token or exact token-bound settled evidence may close execution; current ready token, absent token, dead driver or advanced epoch alone proves nothing. ROUTING_ISSUANCE_UNCERTAIN blocks redispatch/continuation. |
| Exact result-prepared envelope retained | Reconcile engine token; if still awaiting that exact report, resend stepDone only; if already settled, append settlement evidence. Never rerun model. Reuse consumer prepared-artifact recovery. |
| Real retry/new continuation issuance after verified settlement | New token/record, link prior record, reuse validated same-logical-epoch admission. Never assign old token to a new call. |
| Missing/drifted root, input, run link, expected admission/binding, mapping or token index | ROUTING_ROOT_MISSING / ROUTING_ROOT_DRIFT / ROUTING_BINDING_MISSING / ROUTING_BINDING_DRIFT; retain evidence, no model call, no legacy fallback. Applies to ordinary-only runs. |

S1a settlement events are execution safety bookkeeping, not paid-call joins or acceptance. Where S1a cannot prove settlement it refuses; S1b will improve recoverability. A journal token index plus admission references detects missing expected records; never fill holes by recomputing them from today's flags.
