# Build `3e95eb77` — 436,736 tokens for $0.6974. Traced. Cost: $0.

**2026-09-14.** The surviving finding from the ledger rebuild. Question: are the tokens
inflated, or are the dollars missing?

## Answer: missing dollars. compose's arithmetic is faithful.

**Scope of that claim, tightened on review:** the row is an exact sum of what the dispatches
REPORTED. That exonerates the accumulator. It does **not** establish that 425,284 is the true
token count — see the open question at the end, where stratum's own tally contradicts it.

The build made **three** dispatches. Their per-dispatch sums reconcile **exactly** with the
`build-actuals` row — no inflation, no double count, no retry summing:

| seq | ts | step | agent / model | tokens | usd |
|---|---|---|---|---|---|
| 73 | 16:11:11Z | `test_review` | **codex / gpt-5.6-terra** | **425,284** | **null** |
| 75 | 16:14:26Z | `docs` | claude / claude-sonnet-4-6 | 8,073 | $0.5067669 |
| 77 | 16:15:09Z | `docs` (attempt 2) | claude / claude-sonnet-4-6 | 3,379 | $0.1906110 |
| | | | **sum** | **436,736** | **$0.6973779** |
| 79/80 | | `build-actuals` | | 436,736 | $0.6973779 |

**One dispatch is 97.4% of the tokens and carries no dollars at all.** That is the whole
anomaly. `tokens_total` was never inflated, so the S1 accumulator arithmetic is exonerated
again — this is the unpriced-spend family (S1/S2), one layer further out.

## Why that dispatch was unpriced

Traced from the value's set-site outward, not from the shape:

1. **compose recorded what it was given.** `lib/stratum-mcp-client.js:246` writes
   `usd: finiteOrNull(usage.usd)` from the `agent_run` result envelope. The envelope had no
   `usd`, so the row got `null`. compose prices nothing (S3), correctly.
2. **stratum omitted it.** `codexUsageFields` (`ts/src/connectors/codex.ts:603`) emits
   `...(effective > 0 ? { usd: effective } : {})`. **Codex reports no cost of its own** — its
   usage events carry token counts only, and the CLI has no cost tracking — so the accumulated
   `costUsd` stayed `0` and the key was omitted. Omitting is the RIGHT call: it keeps an
   unknown cost unknown instead of stamping a false $0 (the S2 defect).
3. **It was not a stale rate table.** `gpt-5.6-terra` has been in
   `ts/src/judge/pricing.ts` since **`4ac7ad3`, 2026-07-10** — five weeks before this dispatch.
   The rate existed; nothing ever multiplied by it.

## Already fixed upstream, and the fix is live

**stratum `00ff4db` (2026-09-12), "codex must price its own calls; correct stale terra/sol
rates".** `codexUsageFields` now falls back to `usdFromTokens(model, …)` when the connector
reports nothing, labelled `usdSource: "estimated"` — never `reported`, because a consumer may
refuse to reconcile against an estimate. An unpriced MODEL still yields 0 and still omits the
key, so an unknown model stays unknown.

Verified live rather than assumed — compose resolves `@smartmemory/stratum` to the sibling
checkout (0.5.2) and its `dist/connectors/codex.js` carries `usdFromTokens`. Pricing that
dispatch's volume today:

| split | today's figure |
|---|---|
| 400k in / 0 cached / 25,284 out | **$1.1034** |
| 400k in / 380k cached / 25,284 out | **$0.4194** |
| unpriced model | 0 (key still omitted) |

So the build would record roughly **$1.12–$1.81** today instead of $0.6974.

**Limit of that verification, stated plainly:** this is a code read plus a unit probe of
`usdFromTokens`. **No post-fix codex dispatch of real volume exists in this ledger** — the
three codex rows after 2026-09-12 carry 2, 2 and 8 tokens and are fixtures. So the fix is not
yet confirmed to have FIRED on real input, only to be present and to price correctly in
isolation. The next ordinary compose build with a codex step is the free confirmation.

## Correction to my own 0.28x

The "0.28x UNDER" that led here compared **build `3e95eb77` (3 dispatches)** against **flow
`4122e695` (15 dispatches)**. Those are different scopes, so 0.28x overstates the gap. The
under-record is real — 97.4% of the build's tokens carried no price — but the ratio was not
apples to apples, and the flow's other dispatches sit in a different accumulator lifetime
(the `$1.6044701` history row, per 0c).

## Live residue

1. **449,116 of 796,356 tokens (56%) in this project's ledger carry no dollar value.**
   Every unpriced row with real volume is pre-fix: the two 2026-08-18 terra dispatches
   (425,284 + 23,828). The rest are 2-token fixtures or `outcome: error` rows with
   `tokens_total: null`. **But "no live leak" would be asserted on the wrong sample and is NOT
   claimed here:** there is no post-fix codex dispatch of real volume in this ledger at all, so
   this data can neither confirm nor refute that the leak is closed in production. It is
   consistent with closed. The historical rows cannot be repriced regardless — see below.

2. **compose discards the token split on EVERY stratum-routed dispatch.**
   `lib/stratum-mcp-client.js:240-241` hardcodes `tokens_in: null, tokens_out: null`, while
   the SAME FILE at `:873` reads `value.split` off the same result envelope and prefers it,
   with a comment (`STRAT-USAGE-SPLIT`) saying the legacy reconstruction "cannot tell input
   from output and filed the whole aggregate as output for every record ever written".
   Measured: `tokens_in` is null on 36 of 39 stratum-routed claude rows and on 6 of 6 codex
   rows; the 3 populated ones come from `lib/local-claude-connector.js`, which does read its
   capture. **Consequence:** a ledger row records a total only, so no consumer can reprice it
   — input and output differ by 6x on terra — so the 449k unpriced historical tokens cannot be
   repriced **from the compose ledger**. Checked before writing "unrecoverable": stratum's flow
   file is not a fallback either — `4122e695` has `receipts: null` and **zero** occurrences of
   `input_tokens`, `output_tokens` or `cached_input_tokens`. No per-dispatch split survives
   anywhere either side. This is live today.

3. **`usdSource` is dropped by the same call site.** `codexUsageFields` returns
   `usdSource: "estimated" | "reported"` beside `usage`, and `#recordAgentDispatch` reads
   `resultOrError.usage` and `.telemetry` but not `.usdSource`. So **after `00ff4db` the
   ledger row will carry an ESTIMATED dollar figure with no flag saying it is an estimate** —
   which is owed item 2 ("`usd_source` is not carried") arriving on a second surface. It is
   the SAME edit as the split: all three fields sit on the one envelope, all three are read at
   `:873` for the routing record, and all three are dropped at `:240-246` for the ledger row.
   **One call site, three fields.**

**Falsifier:** `lib/stratum-mcp-client.js:240-241`. If those two fields are ever sourced from
`resultOrError.split`, this item is closed.

## OPEN QUESTION — the two systems disagree about tokens by ~15x

Found while checking whether stratum could supply the missing split. **The build↔flow pairing
is confirmed, and by identity rather than by cost:** flow `4122e695` has exactly the steps
compose's rows name — `test_review`, `codex_review`, `docs` — and its `docs` step is `failed`,
matching the build's terminal status.

But that flow's own tally reads `flowSpent: {dispatches: 15, usd: 2.51179065, tokens: 28279}`.
**stratum says the entire 15-dispatch flow was 28,279 tokens; compose says one dispatch inside
it was 425,284.** Even the two claude dispatches (8,073 and 3,379) exceed the flow's
1,885-token average. The two systems are plainly not counting the same thing.

One candidate, unverified: `codexUsageFields` sets `tokens: input + output`, and the connector
comment at `codex.ts:481` records that **OpenAI reports `input_tokens` INCLUDING
`cached_input_tokens`** ("TOKENS STAY RAW"). A heavily cached review would then report a token
count dominated by cache reads, which are billed at 1/10th on terra. `flowSpent` accumulates
through `BudgetLedger` (`engine.ts:2659`) and may exclude them.

**Until this is settled, do not quote 425,284 as a token count, and do not use compose's
`tokens_total` and stratum's `flowSpent.tokens` in the same ratio.** It is also a second
reason the earlier 0.28x was not apples to apples.
**Falsifier: `ts/src/connectors/codex.ts:603` (`tokens: input + output`) against whatever
`BudgetLedger` accumulates.**

## Method note

Three claims in this trace were checked rather than reasoned from shape, and one of them
inverted an assumption: the rate table was the obvious suspect and was **not** the cause
(terra predates the dispatch by five weeks). The dispatch-level reconciliation — three rows
summing exactly to the terminal row — is what made "inflated tokens" falsifiable in one step.
