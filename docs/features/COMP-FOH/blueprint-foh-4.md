> Implementation-time deltas (recorded, not silently diverged): `CONVICTION_STRATEGIES` shipped as a frozen ARRAY, not a frozen Set — `Object.freeze` on a Set leaves `.add()` working, and this is the autonomy gate on a destructive write. `classifyResolution`'s no-op arm compares history CONTENT (JSON-equal), not `history_count` — the real route reads item + history separately (torn reads) and an at-cap history rotates without changing count. The classifier also requires `post.item_id === pre.item_id` and a string event timestamp. The stub gained the real service's `_effective_confidence` legacy bridge (lower `metadata.confidence` wins) and mirrors decay to both the field and metadata.

## File-by-file plan

### 1. `lib/smartmemory-client.js` — two wrappers (mirror `challenge` :444)
- `confidenceHistory(itemId)` — scoped GET `('/memory/reasoning/confidence-history/' + encodeURIComponent(itemId))` via `request('confidenceHistory', (api) => api.get(...))`; `requireShape` validates the COMPLETE envelope (a shaped-but-incomplete 2xx must not classify a destructive write): `typeof raw?.item_id === 'string' && Number.isFinite(raw?.current_confidence) && Number.isInteger(raw?.challenge_count) && Array.isArray(raw?.history) && Number.isInteger(raw?.history_count)`. Envelope: `{item_id, current_confidence, challenge_count, history, history_count}`. Event-field validation happens in the provider's classifier (malformed/NaN → `FluidResolutionIndeterminate`), not here — the wrapper checks the envelope, the classifier checks the events it reads.
- `resolveConflict({ existingItemId, newFact, strategy })` — scoped POST `'/memory/reasoning/resolve'`, body `{ existing_item_id: existingItemId, new_fact: newFact, auto_resolve: false, strategy, use_llm: false, use_wikipedia: false }`, per-call `{ timeoutMs: 8000 }` (3rd arg, like challenge). `requireShape` on `actions_taken` array presence. Returns raw `ResolveResponse` (NOT trusted — see provider).
- Add both to the returned surface object (:503).
- **Do not** re-type transport errors here: `request`/`asHttpError` already yield the `{status:0 | status:200,kind:'malformed-response' | status:N}` taxonomy the provider's Level-1 classifier keys on (`:207-222`).

Confirmed none exist (error block is :184-257).

### 3. `lib/fluid/smartmemory-provider.js` — `conviction()` (replace stub) + `resolveConflict()` + declare cap
- `capabilities()` (:226) — add `CAP.CONVICTION` to the Set (same commit as the methods, D6).
- Shared helper `toConvictionResult(handle, raw)` (used by `conviction()` AND the landed-resolution return): explicit field mapping, no generic camelize helper exists — `{ handle, confidence: raw.current_confidence, challenged: raw.challenge_count > 0, challengeCount: raw.challenge_count, lastChallengedAt: raw.history.length ? raw.history[raw.history.length-1].timestamp : null, history: raw.history.map((e) => ({ timestamp: e.timestamp, oldConfidence: e.old_confidence, newConfidence: e.new_confidence, decayFactor: e.decay_factor, reason: e.reason, ...(e.conflicting_fact !== undefined ? { conflictingFact: e.conflicting_fact } : {}) })) }`.
- `conviction(handle)` (D3): `this.require(CAP.CONVICTION)`; `HANDLE_RE.test`; `item = _resolveOne(handle)` (read-only); null → `FluidRecordNotFound`; `raw = client.confidenceHistory(item.item_id)`; `return toConvictionResult(handle, raw)`.
- `resolveConflict(sourceHandle, targetHandle, { strategy })` (D4) — the load-bearing method. Body runs inside `_withLease('resolveConflict', async () => { ... })` (:691, op-label not id):
  1. Validate `strategy` against `CONVICTION_STRATEGIES = new Set(['accept_new'])` → else `FluidInvalidStrategy`.
  2. Resolve BOTH via **read-only** `_resolveOne` (NOT `_resolveForWrite`): `sourceItem`, `targetItem`. Either null → `FluidRecordNotFound`. (Namespace parity (d) is automatic — `_resolveItems` filters `fluid_ns===RECORD_NS`, :471.)
  3. `sourceRec=_fromItem(sourceItem)`, `targetRec=_fromItem(targetItem)`. **`_fromItem` can return null for a corrupt record blob (:394) even when `_resolveOne` found a namespaced item — `!sourceRec || !targetRec` → `FluidRecordNotFound` BEFORE touching `.kind` (no raw TypeError; add the no-`/resolve`-call test).** Kind gates: `CHALLENGEABLE_KINDS.has(sourceRec.kind)` else `FluidKindUnsupported`; `sourceRec.kind === targetRec.kind` else `FluidKindUnsupported` (naming the mismatched target kind). Self-decay: `sourceItem.item_id !== targetItem.item_id` else throw `FluidInvalidTarget` (a fifth small error class: pre-mutation request refusal — a post-mutation outcome class like `FluidResolutionConflict` must not be reused for validation; carries `{ handle, reason: 'self-target' }`).
  4. `newFact = this._renderContent(sourceRec)` (full text; mirror challenge :1184).
  5. `pre = await client.confidenceHistory(targetItem.item_id)`.
  6. `let resp; try { resp = await client.resolveConflict({ existingItemId: targetItem.item_id, newFact, strategy }); } catch (err) { → Level-1 ambiguous classifier }`.
  7. **Level-1 classify** (design D4): clean success (resp returned) → Level-2; caught `err` with `status` 400–499 & not malformed → authoritative rejection (map 404→FluidRecordNotFound, else rethrow typed); `err.status===0 || err.kind==='malformed-response' || err.status>=500` → bounded reconciliation poll (see below).
  8. **Level-2 classify via ONE pure predicate** `classifyResolution(pre, post, expectedFact)` → `'landed' | 'no-op' | 'conflict' | 'indeterminate'` (module-level function, unit-testable, shared by the clean path AND the reconciliation poll so the two can never disagree). With `expected = Math.max(0, pre.current_confidence - 0.5)`, newest `ev = post.history[post.history.length-1]`:
     - `'landed'` iff `post.challenge_count === pre.challenge_count+1` && `Number.isFinite(post.current_confidence)` && `|post.current_confidence-expected|<1e-9` && `ev` exists with finite `old_confidence`/`new_confidence` && `|ev.old_confidence-pre.current_confidence|<1e-9` && `|ev.new_confidence-expected|<1e-9` && `ev.decay_factor===0.5` && `ev.reason==='manual_resolution:accept_new'` && `ev.conflicting_fact === expectedFact` (caller passes `Array.from(newFact).slice(0,200).join('')`).
     - `'no-op'` iff `post.challenge_count === pre.challenge_count` && `post.current_confidence === pre.current_confidence` (exact — same JSON round-trip both reads) && `post.history_count === pre.history_count`.
     - `'conflict'` iff `post.challenge_count > pre.challenge_count+1`, OR `post.challenge_count === pre.challenge_count+1` but the attribution clause fails (someone else's decay).
     - `'indeterminate'` — everything else (count regression, NaN/missing fields, count unchanged but confidence/history moved).
     Map: landed → `toConvictionResult`; no-op → `FluidResolutionNoOp`; conflict → `FluidResolutionConflict`; indeterminate → `FluidResolutionIndeterminate`.
  9. **Reconciliation poll** (ambiguous transport only): named constants `RESOLVE_RECONCILE_ATTEMPTS = 3`, `RESOLVE_RECONCILE_DELAY_MS = 250` (module-level, test-overridable via the existing pattern for lease backoff). Each attempt: `sleep(delay)`, then `post = client.confidenceHistory(target_id)` — a read that THROWS counts as a failed attempt (never propagates as its own error). Classify each read with the SAME `classifyResolution`: `'landed'` → return success; `'conflict'` → `FluidResolutionConflict`; `'no-op'` is NOT trusted here (the mutation may still be in flight — that is the round-3 race) → keep polling. Window exhausted → `FluidResolutionIndeterminate`. NEVER retry `/resolve`.

### 4. `lib/fluid/ideabox-ops.js` — two consumers (mirror `challengeIdea` :487)
- Both open with **exactly `await gate(ctx)` once** — `gate` (:145) is already `(ctx) => ensureIdeaboxMigrated(ctx.provider, ctx.ideaboxPath)`; do NOT call `ensureIdeaboxMigrated` directly (wrong args) or twice (#6).
- No projection write after resolve: the record body is untouched (only SmartMemory-side confidence moved), so no `project(ctx, …)` call.
- `convictionOf(ctx, id)` → `await gate(ctx)`; normalize `String(id ?? '').toUpperCase()`; `provider.conviction(handle)`; map `FluidRecordNotFound→IdeaboxNotFound`.
- `resolveIdeaChallenge(ctx, id, { against, strategy })` → `await gate(ctx)`; require `against` (else `IdeaboxInvalid('against is required', 'against')`); normalize both; `provider.resolveConflict(sourceHandle=id, targetHandle=against, { strategy })`; map `FluidRecordNotFound→IdeaboxNotFound`; `FluidInvalidStrategy`/`FluidInvalidTarget`/`FluidResolutionNoOp`/`FluidResolutionConflict`/`FluidResolutionIndeterminate` propagate as-is (typed, caller maps once — same convention as challengeIdea :493).
- **JSDoc disclosures (D8, required by the locked design):** `resolveConflict()` and `resolveIdeaChallenge()` JSDoc must state — caller-selected strategy only, never automatic; 0.5 decay is near-irreversible (no fluid reinforce path); intentional repeat calls decay again (1.0→0.5→0.0); of the failure types only `FluidResolutionNoOp` is safe to retry; the caller is trusted to pass an `against` obtained from a real prior `challengeIdea(id)` result (the v1 trust boundary).
